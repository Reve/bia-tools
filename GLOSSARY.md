# Glossary & Academic Tone Guide

## Glossary Terms

### Avalanche Effect
A property of cryptographic hashes where a tiny change in input causes a large, unpredictable change in the output.

### Block
A container that bundles data with metadata (like a nonce) and links to the previous block by storing its hash.

### Blockchain
A sequence of blocks where each block references the hash of the previous block, creating a tamper-evident chain.

### Cryptographic Hash
A function that converts input data into a fixed-length output designed to be deterministic and hard to reverse.

### Deterministic
The same input always produces the same output.

### Difficulty
The requirement for a proof-of-work hash to have a specific pattern (often leading zeros), making it harder to find.

### Fixed Length
A hash output always has the same size, regardless of input length.

### Hash
The output produced by a hash function, often represented as hexadecimal text.

### Immutability
The practical difficulty of changing past data once it is recorded in a blockchain.

### Nonce
A number used once, typically adjusted to find a hash that meets proof-of-work requirements.

### Proof of Work
A mechanism that requires computational effort to find a valid hash, helping secure a blockchain.

### Previous Hash
The hash of the prior block, stored in the next block to create a link between them.

### SHA-256
A widely used cryptographic hash function that produces a 256-bit output.

### Tamper-Evident
A system property where changes are visible because they break expected links or checks.


## Academic Tone & Style Guide

### Voice
- Clear, instructive, and supportive.
- Assume no prior knowledge.
- Use short sentences and avoid jargon where possible.

### Structure
- Introduce a concept with a one-sentence definition.
- Follow with a concrete example or action the learner can take.
- End with a reflective question or summary.

### Language Choices
- Prefer plain verbs like “show,” “compare,” and “observe.”
- Avoid metaphors that require extra background knowledge.
- Use consistent terminology across modules.

### Accessibility
- Prefer high-contrast phrasing for validity states: “valid” and “invalid.”
- Avoid color-only descriptions; always include text labels.
